<Title>React Accordion</Title>
<Subtitle>Accessible disclosure content for product, support, and documentation flows.</Subtitle>

The React package exposes a compound Accordion API that keeps one element per part, supports controlled and uncontrolled state, and preserves the WAI-ARIA accordion relationships for triggers and panels.

## Purpose

Use Accordion when people need to progressively reveal supporting detail without losing the structure of the surrounding page. Good examples include rollout plans, FAQ groupings, pricing clarifications, policy detail, and implementation handoff notes.

## Usage Guidance

- Prefer `button` semantics for the trigger content and keep labels concise enough to scan quickly.
- Use controlled mode when the surrounding page needs to open sections programmatically.
- Use `multiple` only when comparing sections side by side is genuinely useful.
- Provide a stable root `id` when multiple accordions can appear on the same view.

## Accessibility Guidance

- Keyboard users can move between triggers with `ArrowUp`, `ArrowDown`, `Home`, and `End`.
- Triggers expose `aria-expanded`, `aria-controls`, and disabled state consistently.
- Panels expose `role="region"` and `aria-labelledby` so screen readers can connect each panel to its trigger.
- Keep trigger text meaningful out of context so screen reader rotor/navigation lists stay useful.
