<Title>Angular Accordion</Title>
<Subtitle>Accessible disclosure content applied directly to native Angular host elements.</Subtitle>

The Angular package exposes standalone directives instead of wrapper components so each Accordion part can attach to a real native element. That keeps attributes, semantics, and SSR output predictable without adding extra host nodes around the actual trigger or panel elements.

## Purpose

Use Accordion when a page needs progressive disclosure without forcing people to leave the surrounding context. Common examples include release plans, implementation detail, policy explanation, and support handoff content.

## Usage Guidance

- Apply `acAccordionTrigger` to a real `button` whenever possible.
- Use `value` and `valueChange` when the surrounding component needs programmatic control.
- Keep each `acAccordionItem` `value` stable so SSR IDs remain deterministic.
- Prefer one Accordion per information cluster rather than nesting multiple levels.

## Accessibility Guidance

- Triggers support `ArrowUp`, `ArrowDown`, `Home`, and `End` keyboard navigation.
- Panels link back to their trigger with `aria-labelledby`.
- Disabled items expose disabled state without relying on color alone.
- Trigger text should remain meaningful when read out of context by assistive technologies.
